## Deviations and why

- **`tests/projectFiles.test.ts`** (not in B's list): one line changed. It called `projects:stopAnalysis` with a `null` event; with the sender check the spec asks for, that throws. It now passes the app page as the sender; nothing else changed.
- **Private signatures in B's own modules changed** (allowed by §12, "B's own, may change"): `speechOfFile` takes the levels promise as a sixth argument (the `audio_s` bound needs the envelope's length, and the detector's time limit needs the audio length); `RunOptions` gained `stdin: 'none'`, `onSpawnError`; `SpeechRun` gained `limit()` and `stderr()`; `DownloadOptions` gained `onRetry`, `onVerifying`, `retryDelaysMs`, `testBase`, `rename*`; `SpeechModelStore`'s constructor takes optional deps; `LocalClientDeps` gained `processes`, `owner`, `store`, `helper`, `vadModel`, `cores`, `totalMemBytes`, `stallMs`. Exported frozen names are unchanged.
- **Error codes the spec does not map**: helper error `internal` is treated like a crash (one retry with half the threads, verified record kept), `args` and `audio` → `protocol`. An illegal instruction during the probe itself → engine `unavailable` (`cpu`).
- **`.cache` itself** is removed after a successful merge only when it is empty (it may hold the detector's `speech.json`).
- **The `vad` run** is not subject to the 120 s stall rule (it prints one line, at the end); its overall limit (30 s + 50 ms/s) applies.
- No contract (frozen file) was wrong enough to need a workaround.

## Notes for A and C

- **A:** with `--parent-pid N` where N is not the helper's direct parent, the host build exits 2 at once with **no output** (seen when run from a shell pipeline). The app always passes its own pid as the direct parent, and `exec` in `speech-hold-helper.sh` keeps that, so nothing breaks; but an exit 2 without a `cancelled` line is classified as a crash by main. Printing `{"type":"cancelled","done_until":0}` (or an `args` error) there would make it unambiguous.
- **C:** the renderer gets the shared sentences as rejection messages (with Electron's prefix); `localErrorCode` maps all of them (checked end to end below). `TranscribeProgress.phase` is `loading` until the first helper `ready` (a job whose first part is cached goes straight to `transcribing`); `resumed` counts parts taken from the cache.
